# Domain and SEO migration to https://lax360.in

Prepared and tested locally only. Nothing was deployed, committed or pushed. The existing UI, content, backend, database and API behaviour are unchanged.

## What the audit found
The site is a React/Vite single-page app that is **statically prerendered** (`scripts/prerender.js`) into real HTML with its own title, description, canonical, Open Graph and JSON-LD. Every address is built from one setting, `SITE_URL` / `VITE_SITE_URL`; the only hard-coded old address was the fallback default in the build scripts, `.env.example` and `robots.txt`. The sitemap (345 URLs, 3 languages with hreflang) was already limited to public pages (no admin, login, register, password pages, demo, or Play Zone). The admin panel already has SEO management (page titles, descriptions, social images, indexing, canonical, structured data).

## Files changed
| File | Why |
|---|---|
| `frontend/scripts/prerender.js` | Default site address `https://lax360.in`; Organization gets a stable `@id`; new **WebSite** JSON-LD on the home page (no SearchAction: there is no site search) |
| `frontend/scripts/generate-sitemap.js` | Default `https://lax360.in`; regenerates `sitemap.xml` and `robots.txt` (`Sitemap: https://lax360.in/sitemap.xml` and `/sitemap-content.xml`) |
| `frontend/src/hooks/useDocumentHead.js` | In production builds the client-side canonical falls back to `https://lax360.in`, so a page opened on the old or www host still declares the new canonical |
| `frontend/vercel.json` | Two permanent (308) redirects: `www.lax360.in` and `lax360-ventures.vercel.app` to `https://lax360.in/<same path and query>`. `/api/*` and `/_vercel/*` are excluded so API calls and image delivery never break; the destination host has no rule, so no loop is possible |
| `frontend/.env.example` | `VITE_SITE_URL=https://lax360.in` |
| `frontend/scripts/seo-audit.mjs` | New checks: every canonical and sitemap URL is on `https://lax360.in`; the old Vercel address must not appear in any page, sitemap or robots.txt |
| `frontend/public/sitemap.xml`, `robots.txt` | Regenerated by the build |

## Test results (local)
* `npm run build` and `npm run seo:audit`: **0 problems**; 0 occurrences of `vercel.app` in the sitemap, robots.txt, or the home HTML. Remaining audit warnings are existing ones (long Hindi article titles, two short descriptions).
* Sitemap: 345 URLs, all `https://lax360.in`, unique, well-formed XML. Robots.txt: allows public pages, disallows `/company-admin`, `/admin`, `/user`, login/register/password pages, `/demo`, `/api/`.
* Canonical and `og:url` verified in built HTML for `/`, `/about` and an Insights article (also `og:image` on the new domain). JSON-LD present: Organization (+ Place/PostalAddress from the real branch data), WebSite (home), BreadcrumbList (inner pages), Article (Insights). Product/Service/LocalBusiness schemas already exist on their pages and use only data from the site's branch/product records. **Not validated** with Google's Rich Results Test (needs the live URL).
* Redirect rules checked by simulating them on sample paths: `www.lax360.in/about?x=1` and `lax360-ventures.vercel.app/services/web` map to `https://lax360.in/...`; `/api/health` and `/_vercel/image` on the old host are not redirected; `lax360.in` itself is never redirected (loop-free). **Live redirects, HTTP to HTTPS and query preservation are not tested** until the domain is connected (Vercel keeps the query string on redirects and enforces HTTPS automatically).
* No CAD service claim was added.

## Manual tasks (not done)
**GoDaddy (DNS):** add the records Vercel shows for `lax360.in` (apex A record, normally `76.76.21.21`) and `www` (CNAME to `cname.vercel-dns.com`, or the values Vercel displays). For Search Console domain verification, add the TXT record Google gives you.

**Vercel:** add both domains to the project; set `lax360.in` as primary (Vercel then redirects `www` to it; the `vercel.json` rule is a safe duplicate); change the project environment variable `VITE_SITE_URL` (and `SITE_URL` if set) from the old address to `https://lax360.in` for Production, then redeploy; confirm HTTPS certificates are issued. Optionally set `VITE_GSC_VERIFICATION` only if you choose the HTML-tag method (never commit the token).

**Render (backend):** set `FRONTEND_ORIGIN=https://lax360.in` (used for the live content sitemap and password-reset links) and add `https://lax360.in` (and `https://www.lax360.in` while it exists) to `CORS_ORIGINS`; keep the old Vercel origin until traffic has moved. Leave `COOKIE_DOMAIN` unset: the browser calls `/api` on the same domain through the Vercel rewrite, so sessions work on the new domain (users will need to sign in again once, because cookies are per domain).

**Google Search Console:** add a Domain property for `lax360.in`, verify via DNS, submit `https://lax360.in/sitemap.xml` (it links nothing else; also submit `https://lax360.in/sitemap-content.xml`), use "Change of Address" only if the old address was a verified Search Console property, and inspect the home page URL.
